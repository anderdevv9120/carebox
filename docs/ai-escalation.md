# CAREBOX — AI misunderstanding escalation

## Purpose

CAREBOX should ask Bà Lan to clarify an unclear request once. If it still cannot understand, it should notify her daughter (Chị Minh) and record the two unclear messages. Bà Lan can also press **Nhờ con giúp** at any point.

This follows the web-app design in `docs/superpowers/specs/2026-10-18-carebox-webapp-design.md` (Uncertain hand-off) and retains the older demo's one-re-ask rule.

## Issue found (2026-10-18)

Without `GEMINI_API_KEY`, `src/state/assistant.ts` counts unknown messages and calls `handoff()` after two misses. With Gemma enabled, `server/api.ts` sends unknown-intent messages to Gemma and previously reset `misses` and `recentMisses` unconditionally after each successful answer. That prevented the automatic hand-off. The **Nhờ con giúp** button still worked.

Importantly, a message classified `unknown` by the keyword router is *not* necessarily misunderstood. For example, asking for a story or chatting about a song is normal conversation, and should not count as a miss merely because no keyword matches.

## Intended behavior

| Situation | Expected result |
| --- | --- |
| General conversation the model understands | Respond normally; reset the consecutive-miss counter. |
| First genuinely unclear request | Ask Bà Lan to explain again; record the unclear utterance. |
| Next consecutive genuinely unclear request | Create an **AI chưa hiểu yêu cầu** alert, store both utterances, notify Chị Minh, tell Bà Lan her daughter will help. |
| Bà Lan presses **Nhờ con giúp** | Create the same hand-off alert immediately, even with no misses. |
| Recognized emergency or medication-dose request | Use the existing deterministic safety flow; never route it through the free-form AI decision. |
| Google Gemini API unavailable | Report the API error without recording an invented misunderstanding. |

Example: Bà Lan says “Bác muốn nhờ mua cái hôm trước.” CAREBOX asks her to explain. She replies “Cái mà con Minh vẫn mua ấy.” CAREBOX creates an uncertain alert for Chị Minh and tells Bà Lan that Chị Minh has been informed.

## Implementation approach

Use a single Google SDK `gemma-4-26b-a4b-it` request with thinking disabled (`MINIMAL`) for both the conversational reply and a machine-readable clarification decision. The server validates the decision and routes only *genuine* misunderstandings through the existing counter and `handoff()` logic. The existing case/notification UI handles the alert; no new screens or extra AI calls are required.

Keep in mind that the decision is generated by an LLM and may be wrong. A plain-text fallback preserves normal chat if the model ignores the requested JSON format; that fallback cannot guarantee escalation. Live-provider behavior must be verified separately.

## Acceptance checks

- Two genuinely unclear messages with Gemma enabled create one uncertain alert with both utterances and a notification to Chị Minh.
- Two ordinary conversational messages do not generate a hand-off.
- Understanding an intervening message resets the miss streak.
- Manual **Nhờ con giúp** and deterministic emergency handling remain intact.
- Provider failures do not change the conversation or counter.
